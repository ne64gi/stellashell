# Shizuku完全停止時のCapability Matrix（0.7調査）

2026-09-29 / SOG06 Android 14 / scrcpy仮想display 17・1920×1080/160。
**調査のみ。Limited Modeを実装するコード変更はしていない。** REDMAGICは保留。

## 条件と結論

インストール済み0.7.0/code16（星アイコン版）を使用。Shizuku管理アプリのforce-stopに加え、shell UIDの `shizuku_server` とStellaの `desktop_bridge` を停止。Stella本体もforce-stopして再起動。プロセス一覧で、検証中はStella通常UIDのプロセスだけであることを確認した。

既存のオーバーレイ許可・通知アクセス・ウィジェット許可・freeform設定・仮想画面は維持している。**クリーンインストール／Shizuku未導入状態とは同一ではない。** ADBは起動・入力・観測用として使用し、アプリにshell権限を付与していない。

結論：**ランチャー＋ウィジェット＋通知パネルとしてのLimited Modeは成立する余地がある。しかし現状の0.7をそのまま正式なLimited Modeと呼ぶのは不適切。** 開始経路が不統一で、既定のウィンドウ起動は拒否される。自動で通常起動へ切り替わるわけではない。

## Matrix

「実測」はこの端末で操作した範囲。「コード」は接続判定・呼び出し経路の確認で、当該機能の全操作を実機試験したという意味ではない。

## クラッシュと制約

- 試験区間のcrashバッファに新規クラッシュ記録なし。Stellaは通常UIDの同一PIDで継続した。全機能・全端末がクラッシュしないという保証ではない。
- 最初のバー非表示や途中の入力停止は、本体のDozing／復帰タイミングやユーザー操作の重なりがあり、Shizuku不在によるクラッシュとは扱わない。独占操作・Wakeup後に再確認した。
- IMEが `adb input text` の英字を日本語変換する事象があり、ウィジェット検索は既存のUIAutomationヘルパーで文字列を直接設定して確認した。これは通常キーボードの言語切替を直したという意味ではない。
- 未確認：新規インストール、Shizukuアンインストール、物理外部画面、REDMAGIC、本体画面での継続利用、通知アクション、全アプリ／全ウィジェット。
