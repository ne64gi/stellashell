# StellaShell 0.12.0 — 常駐処理・メモリ保持の軽量化

2026-10-13。versionCode: 22 / Shizuku UserService version: 41。
ソースcheckpointです。GitHub ReleasesへのAPK公開は別途扱います。

## 変更

- 同時に要求された本体のタスク一覧取得を共有。完了済み一覧は使い回さず、変更通知・切断・画面の寿命をまたぐ古い結果を防ぎます。
- ジェスチャー入力の行解析で、一時文字列と正規表現処理の繰り返しを削減。新しい周期監視は追加していません。
- 非表示のウィジェットページは、更新の適用を最後の1件にまとめ、表示時に反映します。ウィジェット提供アプリの通信や更新そのものを停止する機能ではありません。
- アプリ名を構成・更新情報付きでキャッシュ。元アイコンのDrawable保持を廃止し、最終表示画像のキャッシュを最大8MiB／64件・長辺256pxに制限しました。画面外・終了済みのアイコン要求と参照を解放します。この上限はプロセス全体のメモリ上限ではありません。
- Dock・Startの通知件数は、接続時の一覧と通知イベントから軽い情報だけで管理。件数を見るだけで本文・画像を含む全通知を繰り返し取得しません。通知欄を隠すと行と本文への参照を解放し、グループの展開状態とスクロール位置を残します。
- カスタム画像ウィジェットは、保存画像を変更せず表示枠のピクセル数に合わせて読み込みます。非表示・停止時に解放し、リサイズ中は旧画像を表示しながら最新サイズへ差し替えます。配置・背景・AppWidgetホストの保存形式は維持します。
- REDMAGIC NX809J／Android 16の小窓固定経路を本体画面に限定して追加。外部画面の固定は有効にしていません。固定UIの一連の操作については下記の未確認事項を参照してください。

## 検証範囲

機能変更部分は、0.11.1表記の開発APKでSOG06（Android 14）とREDMAGIC NX809J（Android 16）へ導入・検証済みです。0.12.0では版番号を更新し、ビルドを確認しています。版番号だけでAPKの同一性は判定しません。

- JVMテスト327件成功、全モジュールのlintエラー0件（警告は残存）、debug／AndroidTest APKのビルド成功。
- 両端末の合成データによるアイコン描画・キャッシュ上限・古い要求の破棄、通知のグループ分け／件数／表示／スワイプ、カスタム画像の解放／復帰／リサイズ試験に成功。
- 通知の合成テストでは、500回の更新と2,000回の件数参照に対して、全通知取得は接続時の1回。実際の通知トラフィックを計測した値ではありません。
- 画像の合成テストでは、1600×800pxの保存画像を400×150pxの枠用に300×150pxで読み込み、画像メモリは180,000バイト以内。保存画像は変更しません。
- タスク一覧の同時要求・切断・遅延応答、非表示ウィジェットの更新適用と復帰はREDMAGICの合成native試験でも確認。提供アプリ固有の更新や全OEMの保証ではありません。

## 未確認事項

- 利用者からPensumで271MB・安定との報告がありますが、指標の同定と同一操作条件での比較は未完了です。更新時の再起動も挟んでおり、特定の削減率や電池消費の改善は保証しません。
- 確認時点では両端末にカスタム画像ウィジェットはなく、上記の画像テスト結果を実際の使用量低下の原因にはしていません。実画面での画像ウィジェットの連続編集・ページ操作は未確認です。
- 通知のranking変更は型付き入力の合成試験で検証。実際のAndroid RankingMapの配達から件数表示までを独立した通し試験で確認したわけではありません。
- REDMAGIC本体の固定はnativeの固定／解除・フォーカス・最小化復帰等を検証していますが、実際のタイトルバー固定ボタン、物理キーボード／IME、実Binderプロセス終了の網羅は未完了です。SOGの既存経路と外部固定の制限を維持します。
- 長時間使用でのメモリ再増加、CPU・電池の同条件比較は継続課題です。
